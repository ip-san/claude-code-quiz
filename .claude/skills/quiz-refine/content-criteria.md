# Quiz Refine — コンテンツ選定基準

overview タグ付き問題（全体像モード）とシナリオ問題、および `src/data/scenarios.ts` 改善時に適用する。

## 全体像モード・シナリオの問題選定基準

### 含めるべき問題
- **実践テクニック:** 「こう依頼するとうまくいく」「こう使い分ける」
- **ベストプラクティス:** 効果的な依頼方法、軌道修正、コンテキスト管理
- **判断力を問う問題:** 「いつ使うか」「なぜこの方法が良いか」
- **失敗回避:** 「無限探索を止めるには」「暴走を防ぐには」
- **上級テクニック:** 難易度は問わない。実践的であれば advanced も可

### 含めてはいけない問題
- **内部ツール名の暗記:** Grep/Glob/Read/Write/Edit/Bash の使い分け（AI が自動選択する）
- **設定ファイルのパス暗記:** ディレクトリ構造、ファイル名の暗記
- **プロトコル・トランスポートの詳細:** stdio/HTTP/SSE の違い
- **フックイベントの内部動作:** PreToolUse vs PostToolUse の発火タイミング（ただし、advanced シナリオで具体的なビジネス要件の文脈がある場合は許容）
- **構文暗記:** @メンション構文、YAML フロントマターの書き方
- **消去法のトリビア:** 「含まれないものはどれ？」型の問題

**判定基準:** 「ユーザーがこれを知っていると、明日の仕事で何か変わるか？」
変わるなら含める。変わらないなら各カテゴリの専門学習に譲る。

## 実践シナリオの品質基準

### ナラティブの品質

各ナラティブは以下の3要素を少なくとも1つ含むこと:

1. **現場の知恵**: ドキュメントに書かれていない経験者の教訓
2. **失敗の具体描写**: 何を間違えるとどうなるか
3. **感情的フック**: 読者が「自分ごと」と感じる緊迫感・達成感

### ナラティブのNG パターン

- **段取り説明のみ**: 「次はXXしよう。YYを確認しておこう」→ なぜ重要か・失敗するとどうなるかを追加
- **ドキュメントの要約**: 「MCPとは外部ツール連携の仕組みです」→ 問題が教える内容をナラティブが先取りしない
- **文脈なき問題導入**: 「ショートカットを覚えておきたい」→ どの場面で必要になったか（Claudeが暴走した、テスト中に別タスクが来た等）を具体化

### ストーリーアーク

導入→上昇→転換→解決の4段階構造。ナラティブと問題の難易度・文脈を一致させる。問題数は7問以下。
